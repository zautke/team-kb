  collector contrib 0.158.0, `TeamKb.OtlpBridge` (built from source by

  redaction allowlist (mirrors `Telemetry.cs`) → 1 KB truncate → D3

- `deploy/otel/otel-stack.sh` — up/down/status/logs/validate/smoke; `smoke`
  sends a synthetic OTLP/JSON span and asserts it lands in the bridge sink.
- `src/TeamKb.OtlpBridge/` — the D0 gap-closer: OTLP/JSON → Cosmos documents

  Standalone project — NOT added to TeamKb.sln (no build-host dotnet dependency;
  compose builds it).
- `docs/research/otel-agentic-csharp/09-local-deployment.md` — detailed
  machine-agnostic runbook (quick start, app wiring, Cosmos options, Azure

## Live verification (2026-08-17, Docker on the authoring machine)

Full stack executed end-to-end with BOTH lifecycle scripts. Three real
defects found and fixed by running (none were visible statically):

1. **ps1 `.env` parser kept inline comments** — `PORT=18901  # comment`
   became the literal value → compose `invalid hostPort`. Bash `source`
   strips comments natively, so only the PowerShell twin broke. Parser now
   strips ` #…`, trims, and unquotes.
2. **Cosmos SDK 3.62.0 requires an explicit Newtonsoft.Json reference** —
   bridge image build failed in `dotnet publish`; added Newtonsoft.Json
   13.0.4 to the csproj.
3. **Collector otlphttp exporter gzips by default** — bridge returned 400 on
   every real export (collector: "Permanent error … HTTP Status Code 400",
   data dropped). Bridge now decompresses when `Content-Encoding: gzip`.

Also added `$LASTEXITCODE` guards to ps1 `up`/`validate` (PowerShell does not
propagate native exit codes; `validate` previously printed "valid" after a
docker failure).

Evidence: `./otel-stack.ps1 -a up` → 3 containers Up; `-a smoke` → `SMOKE
PASS: span reached the bridge file sink`; same via `otel-stack.sh`; `-a
status` → collector health OK + bridge sink `file:/data/spans.jsonl`; span
document verified (`sessionId` partition key, full OTLP span embedded); zero
collector export errors post-fix; Aspire UI responding. Phase 1 exit
criterion (real MCP-host trace tree in Aspire) still pends a machine with
both dotnet and Docker — team machine captures that screenshot.
